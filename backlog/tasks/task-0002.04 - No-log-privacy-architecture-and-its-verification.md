## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
P4 complete (2026-08-04). Model that actually served: claude-opus-5[1m]. All ten Phase 4 boxes ticked in specs/001-address-search-school-proximity/tasks.md; full notes there. Suite: docker compose --profile test run --rm test -> 107 tests, 0 failures (was 43).

THE FINDING: the log-capture test found THREE real leaks of the searched address, none of them in somap's code. React Router's default handleError console.error's 'No route matches URL "/search/<the address>"'; its default root error boundary console.error's the same object again while server-rendering the 404 (and emits an inline <script> that script-src 'self' blocks); and @mjackson/node-fetch-server's defaultErrorHandler does the same, reached through @react-router/node's createRequestListener, which does not expose the onError option that would replace it. Each closed at its source (app/app/entry.server.tsx ejected via react-router reveal, a root ErrorBoundary that never touches the error, the wrapper in server/http.ts) -- but three sites in one 7.x minor means a fourth arrives with any dependency bump, so the request process now SEALS its own output after the startup line (app/server/silence.ts). docker compose logs app is one line for the life of the container. Accepted cost, stated in every file it touches: a running-server fault is not diagnosable from its output.

PostgreSQL: the three settings the box named were already the image default, which is not a control. The two that were NOT default are the ones that carried the leak -- log_min_error_statement (defaults to 'error': logs the full text of any failing statement) and log_parameter_max_length (defaults to -1: logs bind parameters IN FULL). The address travels as a bind parameter. All set as command-line flags in docker-compose.yml, so pg_settings.source reads 'command line' and ALTER SYSTEM SET log_statement='all' cannot override them -- verified.

Proof the gate bites, not just passes: overriding db with log_statement=all makes 11 tests fail and puts DETAIL: Parameters: $1 = '1464 Garman Rd, Akron, OH 44313' in the database log verbatim. Override removed, never committed.

CSP forced a real decision: script-src 'self' with no unsafe-inline and no nonce is incompatible with React Router's hydration bootstrap (three inline scripts). Softening the operator-signed policy was not an option, so somap now ships NO client-side JavaScript -- <Scripts/> removed from root.tsx. Costs nothing R1 wanted; every Phase 5 box already required JS-off operation. Phase 5 may not add a component requiring hydration without an operator CSP amendment.

Pre-existing defect fixed: createRequestListener does not serve build/client, so every /assets/* URL had 404'd since Phase 1 -- unnoticed because nothing referenced one until this phase added a stylesheet. A 404 stylesheet is a privacy defect: the next person to find the page unstyled reaches for a CDN. app/server/static.ts serves them, in-process, with resolved-path containment.

A control implemented and reverted, recorded rather than omitted: a docker network with internal:true would be the strongest form of FR-024, but the engine will not publish a port for a container on an internal network (PortBindings populated, NetworkSettings.Ports empty, host connection refused). app cannot be both isolated that way and reachable. Documented in docker-compose.yml and docs/privacy/verification.md section 6, including how a self-hoster behind their own proxy CAN have it.

docs/privacy/verification.md is written for a reader who does not trust us: exact commands, expected output, and a whole section on how to MAKE EACH CHECK FAIL.
