## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Decide, with a concrete disclosure design in hand, whether somap keeps shipping zero client-side JavaScript or amends its Content-Security-Policy to admit a per-response nonce for hydration.

Raised during TASK-0002 P4. The zero-JS state was not chosen and was not required by any principle. It fell out of the CSP written into the TASK-0002 sweep runbook -- script-src 'self' with no nonce and no hash allowance -- which is incompatible with React Router 7's hydration bootstrap, because that bootstrap emits inline script tags carrying serialized loader context. P4 hit the gate, correctly refused to soften an operator-signed policy, and removed the client bundle instead.

Hashes cannot resolve this: the context script's content varies per request because it embeds loader data, so script-src 'sha256-...' cannot match. A nonce is the only route to hydration.

The decision belongs here rather than in TASK-0002 because this task is the first work with an actual interaction that might want it. Deciding it earlier would have meant amending a privacy gate for a capability nothing had asked for.

The case for staying at zero JS, recorded so it is not re-derived: with no scripts, verifying the privacy claim is view-source and count script tags, which a caseworker can do; with a bundle it becomes read and trust 200KB of minified JavaScript, which only a specialist can do and only once. Principle III's audience is a population failed by systems claiming to help it, so a check they can run themselves outranks one they must trust. Hydration also puts the searched address into client router state, widening the surface for the datum the constitution singles out as uniquely dangerous. And in TASK-0002 P4, three separate leaks of the searched address were found inside one React Router 7.x minor -- all in dependencies, all on error paths; a client bundle is the same failure mode on a larger surface with no log to grep.

The case against: shadcn's value is its Radix-backed interactive components, which do not degrade without JavaScript, so zero JS effectively rules them out. Note that the TASK-0002 runbook already forbade those primitives for the coverage manifest on exactly those grounds, so the load-bearing surface was never going to use them.

Whichever way this goes, record it as a decision with its reasoning rather than as a config change.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
First-party JavaScript is permitted. The CSP now carries a per-response nonce (16 bytes, node:crypto randomBytes, base64) minted in app/app/entry.server.tsx and set on the document response there; every other directive is unchanged, and no third-party origin is admitted anywhere. Non-document responses (assets, raw 400s, 500s) keep a script-free policy with script-src 'none'.

The zero-JS state was never a decision. It fell out of the script-src 'self' string the TASK-0002 runbook specified in Lane 0, which React Router 7's hydration bootstrap cannot satisfy: the bootstrap emits inline scripts carrying serialized loader context, and hashes cannot match content that varies per request. Phase 4 hit the gate, correctly refused to soften an operator-signed policy mid-phase, and deleted the client bundle instead. Everything written since defended that accident as though it were a principle.

Verified against artifacts rather than assumption: the constitution's Principle III bans third-party scripts, analytics, and request logs -- not first-party JavaScript. FR-025 and FR-026 are origin-scoped and are satisfied by a first-party nonce. The runbook itself records at its 2026-08-04 checkpoint that zero-JS was required by no principle.

The spike's chief privacy objection was narrowed but not dismissed. action() in app/app/routes/answer.tsx returns only search()'s result, and SearchResult carries the county's label for the matched parcel, never the typed string -- so the hydration context does not contain the searched address. The related objection was real: the serialized staticHandlerContext would have carried error objects, and those can hold the request that produced them. entry.server.tsx now scrubs every error in the handoff to a bare {status, statusText} before ServerRouter sees it. The existing suite caught this immediately.

Gates amended to assert the property that matters rather than the accident: http-headers.test.ts now requires a nonce in script-src and still forbids 'unsafe-inline', 'unsafe-eval', and *; asserts every script in the document is same-origin and carries the response's nonce; and checks entropy and per-response uniqueness across 100 draws. copy.test.ts forbids off-origin scripts and now strips <script> blocks before its body-text scans, so escaped strings inside the hydration payload can no longer be read as visible copy. browser/form.test.ts asserts every script request is same-origin. The two tests that prove the flow works with JavaScript disabled (SC-001) and that <details> disclosure needs no script (FR-015) are untouched and still pass -- they are now a choice rather than a constraint.

docs/privacy/verification.md replaces 'view source and count script tags' with a check of comparable cheapness: curl the headers twice and observe the nonce differs, then grep the script tags and observe every src is a relative path. A script carrying a stale nonce does not run. The TASK-0002 runbook's Lane 0 CSP clause is amended in place with a dated blockquote rather than rewritten.

Recorded as docs/decisions/task-0008-01-nonce.md, alongside spikes/task-0001-geocoding/DECISION.md and matching its format.

Hydration is enabled, not adopted. No component was converted to require it in this work.

Tests: 218/218 pass. Commit fd36551 on task-0008-01-nonce.
